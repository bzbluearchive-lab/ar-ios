# 走 kfd 但不想拿主力机冒险：怎么拆

## 核心结论

风险能不能挪走，取决于有没有一台**与主力机同 iOS 版本、同 ABI** 的设备。
6s（15.8 / arm64）不合格——它的内核侧数据一个都不能用。

需要的是：**arm64e + iOS 16.1.1**。

| 候选 | 芯片 | 能停在 16.1.1 | 能否当影子机 |
|---|---|---|---|
| iPhone XS / XR | A12 | ✅ | ✅ 最便宜可用 |
| iPhone 11 系列 | A13 | ✅ | ✅ |
| iPhone 12 / 13 | A14/A15 | ✅ | ✅ 但贵 |
| iPad 8/9 代 | A12/A13 | ✅ | ✅ 屏幕大，调试方便 |
| **iPhone 6s** | A9 (arm64) | 15.8 | ❌ 版本 + ABI 都不对 |

**A12 与 M2 同属 arm64e、同一 iOS 构建**，`proc` / `task` / `vm_map` 这些结构体的字段偏移由 XNU 构建决定，同一 build 上基本一致；PAC 密钥不同，但我们不需要 PAC 密钥（只读写内核数据与代码段）。
所以 A12 影子机上算出来的偏移与补丁方案，在 M2 上大概率直接可用，只需回读验证。

## 影子机上要完成的全部工作

| 步 | 内容 | 在影子机上做完意味着 |
|---|---|---|
| 1 | kfd 分支选型与初始化（按 16.1.1 / arm64e 核对支持表） | 知道能不能跑，不碰主力机 |
| 2 | 内核基址 + 读自检（读自己 `proc`，校验 `p_pid`） | 地址算对了 |
| 3 | 定位 `task_for_pid` 的检查点（符号扫描 / 特征扫描） | 补丁点确定 |
| 4 | 补丁字节 + 回读校验 + 撤销按钮 | 补丁可逆、可验证 |
| 5 | 注入链验证：`vm_allocate` 从 `0x10000003` 变 0 → 注入 SpringBoard → 绿框 | 整条路通 |
| 6 | 把这套做成按 iOS 构建号索引的偏移表 | 产品化雏形 |

**第 5 步在影子机上通不过，就不要上主力机。** 这是关键的分界线。

## 主力机上只做一件事

**跑影子机上已经完全通过的同一个构建。** 不做探索、不做试错、不调参数。

具体：影子机验证通过后，把同一个 ipa 装到主力机，跑一次，看日志里
`vm_allocate -> 0`、`thread_resume -> 0`、绿框出现。一次成功就结束。

## 主力机风险的六条工程纪律

| 纪律 | 具体做法 |
|---|---|
| **只写代码段，绝不写数据段** | 补丁只落在 `__TEXT_EXEC`；数据段里可能有映射到磁盘缓存的内存，那是唯一"可能坏数据"的场景 |
| **写前备份、写后回读** | 每次 `kwrite` 前 `kread` 原字节；写完立刻回读逐字节比对；不符立即写回 |
| **补丁最小化** | 只改 1~4 条指令，绝不改函数指针表 / 结构体字段 |
| **零持久化** | 不写 launchd、不改启动脚本、不碰 rootfs → **重启即完全清除**，没有 bootloop 面 |
| **默认关闭** | 所有危险动作放在显式开关后面，默认不开；app 启动不做任何内核操作 |
| **每次开测前备份** | Finder / iTunes 加密备份一次；万一极端情况需要 DFU，损失可控 |

按这六条走，主力机上最坏的现实结果是 **panic → 设备自动重启 → 数据完好**。
这不是"理论保证"，是基于"我们从不写磁盘"这个事实：panic 发生在内存里，重启后内核从磁盘重新加载，一切回到原样。

## 唯一不能靠纪律消除的残留风险

如果补丁本身把内核状态改坏到"下次启动时内核在早期崩溃"，理论上是可能的——但那要求我们改的是**持久化配置**（nvram、启动项、rootfs）。我们的补丁落在 `__TEXT_EXEC`，只影响当前这次运行的内存副本。**重启后内核从磁盘重新加载，补丁消失。**

所以纪律里最重要的是那条"零持久化"。守住它，风险就被限制在"一次重启"这个量级。

## 产品化角度（这才是真正的长期成本）

产品要支持多个 iOS 版本 / 多种设备，意味着：

```
偏移表按 build 索引
  iOS 16.1.1 (20B101) / arm64e  -> { kfd 分支, proc_off, task_off, patch_site, patch_bytes }
  iOS 16.6   (20G75)  / arm64e  -> { ... }
  ...

启动时：
  读到 build -> 查表
  查不到 -> 立刻停止，什么都不做（绝不猜）
  kfd 初始化失败 -> 立刻停止
  第 2 步自检不过 -> 立刻停止
```

**"失败即停"是产品里最重要的一条**：任何一步校验不过，就不往下走。
这比"想办法兼容"重要得多，因为猜错的代价是用户的设备。

## 成本对比

| 方案 | 一次性投入 | 主力机风险 | 开发效率 |
|---|---|---|---|
| 直接主力机试错 | 0 | **高** | 低（每轮 CI + 手动装机 20 分钟） |
| **买 A12 影子机** | 几百到一千多 | **≈0** | 高（随时试、随时重启） |
| 用 6s | 0 | 中（内核侧仍要主力机验证） | 中（机制可以，内核不行） |

## 我的建议

买一台二手的 **iPhone XS / XR 停在 iOS 16.1.1**（或 iPad 8/9 代），当影子机。

理由：
1. 同 build → 内核偏移与补丁方案直接可用，不用二次推导
2. 几百块的设备换掉主力机的全部内核风险
3. 开发迭代快十倍：随便 panic、随便重启，不用备份不用小心
4. 产品化需要的那张偏移表，正好在它上面长出来

6s 别浪费——它可以做**越狱机制验证**（浮窗、W2S、hook 时序），那部分和设备无关。
