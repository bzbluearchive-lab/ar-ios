# 每步操作的最坏结果与恢复

先给结论：**本方案的全部操作都在用户态进程内，磁盘零修改，不涉及开机链。**
设备层面最坏的结果是 **respring（黑屏几秒回桌面）或需要强制重启**。
白苹果（卡苹果 logo 起不来）需要破坏 rootfs / dyld shared cache / 内核缓存 / 启动脚本，
这些我们一步都不碰。

---

## 逐条对照

| # | 操作 | 最坏结果 | 影响面 | 恢复方式 |
|---|---|---|---|---|
| 1 | TrollStore 安装 ipa | 装不上 / 图标残留 / LaunchServices 注册脏数据 | 该 app 本身 | 长按删除；TrollStore 里 Uninstall；必要时重启 |
| 2 | 启动 app（带私有权限） | 启动即退，无崩溃日志 | 该 app 本身 | 卸载即可，无残留 |
| 3 | 暴力扫 pid（`task_for_pid` 1..1024） | 每次失败只返回错误码；成功的端口我们立刻 `mach_port_deallocate` | **零** | 无需恢复 |
| 4 | 读目标进程的 dyld 信息 | 只读操作，失败返回错误码 | **零** | 无需恢复 |
| 5 | 在目标进程里 `vm_allocate` + `vm_write` | 目标进程内存多占一页；写入后目标不认识这块内存 | 仅目标进程 | 目标重启即清空 |
| 6 | 远程 `thread_create` + `dlopen` | **目标进程崩溃** → 若目标是 SpringBoard，表现为 respring（黑屏几秒回桌面） | SpringBoard 重启，桌面图标重排 | 自动恢复；不自动恢复就强制重启 |
| 7 | payload 的 constructor 死循环 | SpringBoard 反复重启（respring 循环），桌面进不去 | 桌面不可用 | **强制重启**（音量+ → 音量- → 长按电源） |
| 8 | payload 建超高 `windowLevel` 窗口 | 如果 `hitTest` 没做穿透，可能挡住触摸导致点不动屏幕 | 触摸被遮 | 强制重启 |
| 9 | 写日志 / 共享内存 | 占几十 KB 磁盘 | 零 | 删文件 |

## 不会做的事（这些才是白苹果来源）

| 不做 | 原因 |
|---|---|
| 修改 `/` 根分区、`/System/Library` | 破坏系统卷 |
| 装 `launchd` 守护进程 / 改启动脚本 | 开机路径被污染 |
| 改 dyld shared cache 或内核缓存 | 启动失败 |
| 用内核原语（kfd / libkernrw / tfp0） | 写错内核结构 → panic，这是本机唯一能"变砖级"的操作面 |
| 系统改过之后走 OTA 更新 | 更新校验失败 → 白苹果 |
| 越狱（Dopamine / palera1n） | 引入另一套风险面，本方案不需要 |

## 两级恢复手段

| 级别 | 手段 | 何时用 |
|---|---|---|
| 一级 | 长按删除 app | 大多数情况 |
| 二级 | **强制重启**：音量+ 按一下松开 → 音量- 按一下松开 → 长按电源键约 10 秒 | respring 循环 / 触摸被挡 / 桌面卡死 |
| （不需要） | DFU 恢复 | 本方案触及不到的层级 |

**为什么强制重启一定有用**：我们没有注册任何开机自启的东西。
payload 只在内存里，app 也没有 launchd 项，所以断电重启后设备回到完全干净的状态。

## 代码里已经做的保护

| 保护 | 位置 | 作用 |
|---|---|---|
| 只注入路径匹配 `SpringBoard` 的进程 | `find_by_bruteforce` | **绝不往身份不明的进程里注入**；扫描阶段只读不写 |
| 扫描与注入拆成两个按钮 | 主界面 | 可以先只跑安全的扫描 |
| `hitTest` 默认返回 nil | `SBWindow.mm` | 窗口不拦截触摸，避免挡住系统 |
| payload 全部逻辑挂在 `dispatch_after` 里 | `SBWindow.mm` | 不阻塞 SpringBoard 启动 |
| payload 不写磁盘、不注册任何服务 | 全工程 | 重启即彻底清除 |

## 唯一一处"理论上可能更糟"的地方

第 6 步（远程 `thread_create` + `dlopen`）。
如果目标进程不是 SpringBoard 而是 `launchd` / `backboardd` 这类更底层的进程，理论上可能导致
整机 UI 卡死或重启。代码上已经排除这种情况：**只有路径里含 `SpringBoard` 才会进入注入分支**，
其余全部跳过。

真出现这一步的最坏情况，仍然是强制重启能解决——因为没有任何东西写进磁盘。
